# 概念 FAQ(AI 助教回答"为什么"类问题时使用)

每条给:**一句话版**(当前阶段够用)· **深入版在哪** · **关联编号**。
原则:先用一句话版回答;学员追问且阶段到了,再给深入版的链接。

---

### Q1 为什么用 VPS,不用 Serverless / Vercel / 云函数?
- 一句话:这门课教的是"部署的底层共同骨架"(systemd、反向代理、备份、回滚),PaaS 把这些藏起来恰恰学不到;而且大量真实业务仍跑在"一台服务器"上。
- 深入:README 学习路线 · P13。
- 阶段注意:学员若真实项目适合 PaaS,尊重其选择,说明取舍即可。

### Q2 为什么应用本身不用 Docker 跑,只用 Docker 跑 Postgres?
- 一句话:教学上想让学员直面 systemd、进程、信号、日志这些每一层都能摸到的东西;单容器化一个单机应用收益有限、抽象层加一层(P13)。Postgres 用容器是因为装配干净、数据卷隔离好。
- 深入:高级第 9 章"何时上镜像 + registry"有触发条件。
- 关联:P13。

### Q3 为什么不用 pm2 / supervisor,要用 systemd?
- 一句话:systemd 是发行版自带的、无第三方依赖的"1 号进程下属",开机自启、依赖顺序、日志、资源限制、加固选项全都原生;pm2 解决的"守护"只是它能力的一小部分。
- 深入:初级第 4 章逐行讲解。
- 关联:P13。

### Q4 为什么不直接上 Kubernetes?
- 一句话:K8s 解决的是"多机编排、自愈、弹性",你的场景(1 台机器、1 个服务)里这些问题不存在,而它引入的成本(集群自身运维、凭证、网络)从第一天就在。
- 深入:高级第 9 章决策表(触发条件:机器 >10 / 服务 >15 / 有专职平台人力 / 需要频繁弹性伸缩)。
- 关联:P13。

### Q5 为什么在生产服务器上构建?这不危险吗?
- 一句话:参考设计接受了这个代价(简单、少一套产物基建);它的问题(H7:抢资源、依赖外网、不可复现)是真实的,中级先隔离风险(.partial、预检),高级用 D1 对比实验决定要不要换 CI 构建。
- 深入:中级 7.3 + 高级第 3 章。
- 关联:H7、D1、P1。

### Q6 为什么要 root / deploy / app 三个用户?好麻烦。
- 一句话:最小权限(P7)——想象最坏情况:CI 钥匙泄露,攻击者拿到的 deploy 身份读不到数据库密码、改不了部署脚本、开不了 shell,只能触发一次 main 上的合法部署。
- 深入:中级第 2 章角色表 + 第 3/4 章逐条验证。
- 关联:P7、A1/A2。

### Q7 部署时为什么会丢请求?能完全不丢吗?
- 一句话:重启窗口内进程不在,正在建立的请求会失败(优雅退出能救在途的);原子切换把窗口缩到最小,蓝绿(新旧并存 + Nginx 原子 reload)能到接近 0。
- 深入:初级 7.3(测量)→ 中级 7.5(原子切换)→ 高级第 2 章(蓝绿)。
- 关联:E1、D3。

### Q8 迁移失败了会丢数据吗?回滚会不会回滚数据库?
- 一句话:每个迁移文件一个事务,失败整体回滚且代码不切换,线上无恙;**数据库永远不自动回滚**(自动回滚数据才是灾难),兼容性靠 expand/contract 两阶段保证。
- 深入:中级 7.4 + 高级 6.1(回滚安全矩阵)。
- 关联:P2、D3/D4 场景。

### Q9 三个 .env 文件到底有什么区别?
- 一句话:①仓库的 `.env.example`(只有变量名的模板,进 git);②compose 旁边的 `.env`(只放 Postgres 密码,给容器初始化用,不进 git);③`runtime.env`(应用全部运行时配置,root:app 0640,deploy 读不到)。②③里的密码必须一致。
- 深入:初级 3.4 + 中级 2.2。
- 关联:P7。

### Q10 健康检查为什么要那么复杂?curl 通了不就行?
- 一句话:端口通了 ≠ 新版本正常——三种假阳性(旧进程还在应答、worker 崩溃但 web 正常、起来 10 秒就崩)只有"断言 SHA + 心跳 + soak 窗口"能抓住,中级剧本 6 会现场演示漏掉它们的后果。
- 深入:中级 7.5 + 剧本 6。
- 关联:P3、P4、E2。

### Q11 回滚为什么是单独的 rollback.sh,不能重新部署旧 SHA 吗?
- 一句话:部署管线会拒绝"比线上旧的 SHA"(B2 防线,防止排队乱序);而回滚必须快、离线可用、不碰数据库——这些要求和部署管线完全不同,所以是一等公民命令(P9)。
- 深入:中级 7.2 + 第 10 章 runbook。
- 关联:H8、E7、P9。

### Q12 为什么 GitHub Actions 里手写 ssh,不用现成的 action?
- 一句话:5 行手写 ssh 让你看得见每一次连接(密钥怎么进、host key 怎么固定);供应链上每加一个 action 就多一分风险。理解了再换不迟。
- 深入:中级 8.1。
- 关联:P7、A5、P13。

### Q13 SSH 端口开着不怕被爆破吗?
- 一句话:已经叠了三层:强制命令(门后只有一条缝)+ fail2ban(封爆破源)+ 密钥登录(猜不动);彻底方案是 Pull 模式把入站 22 整个关掉。
- 深入:中级 3.3 + 高级第 4 章。
- 关联:H10、D2。

### Q14 部署脚本改了,为什么线上不生效?
- 一句话:设计如此——服务器上的部署脚本 root 拥有、需手动重跑 install.sh 更新(H11 的漂移问题),高级册 7.5 加了指纹对账让漂移可见。
- 深入:中级 2.3 + 高级 7.5。
- 关联:H11、F2、P11。

### Q15 备份到底怎么做才算"做了"?
- 一句话:做过恢复演练才算(P5)——GitLab 2017 丢库事故里所有备份机制都"存在"但都不能用。能说出你的 RPO/RTO 数字,备份才算存在。
- 深入:初级第 6 章 + 高级 6.4(实测表)。
- 关联:P5。

### Q16 我的业务应该用 Push 还是 Pull / 要不要蓝绿 / 要不要 CI 构建?
- 一句话:教程刻意不给唯一答案,高级册每项都有"假设→实验→结论→升级触发条件";用你自己的数据对表。
- 深入:高级第 2/3/4 章 + 第 9 章决策表。
- 关联:D1–D4、P13。
